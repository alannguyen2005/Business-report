# Descriptive Analysis Principles

## 1. Conclusion-First
Every output leads with the insight:
- BAD: "Revenue was $2.1M in Q1 2026"
- GOOD: "Revenue fell 18% ($460K) in Q1, breaking a 6-quarter growth streak"

## 2. So-What Test
Every finding must pass: "If I remove this finding, does the analysis lose something?"
- If no → cut it
- If yes → keep it and make the "so what" explicit

## 3. MECE (Mutually Exclusive, Collectively Exhaustive)
Segments must:
- Not overlap (each record belongs to exactly 1 segment)
- Cover 100% of the data (no records left uncategorized)

## 4. Comparison is Everything
A number without comparison is meaningless:
- vs. prior period (MoM, QoQ, YoY)
- vs. benchmark/target
- vs. other segments
- vs. expected range

## 5. Signal vs. Noise
Not every fluctuation is a finding:
- Random variation: <1σ from mean → not a finding
- Possible signal: 1-2σ → note but don't overstate
- Strong signal: >2σ → flag as finding

## 6. Base Rate Fallacy
Always check absolute numbers alongside percentages:
- "Segment X grew 200%" sounds impressive
- But if Segment X is 1% of revenue, it's noise
- Report both relative AND absolute impact

## 7. Avoid Anchoring
Don't let the first number you see anchor the analysis:
- Check multiple time windows
- Check multiple dimensions
- Check if the "normal" baseline is actually representative
